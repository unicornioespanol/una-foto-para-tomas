# Una foto para Tomás — технический бриф реализации

Версия 1.1 · 22 октября 2026 · язык книги: испанский · дети 7–10 лет.

## 1. Результат

Создать адаптивную интерактивную HTML-книгу по утверждённому сценарию: подготовка к чтению → чтение с временной браузерной озвучкой → задания после чтения. Два сюжетных выбора; на одном прохождении 9 экранов, включая 2 развилки. Всего 13 узлов сценария. Самостоятельное чтение и чтение с учителем равноправны.

Сценарий, язык и принятый визуальный образ не менять при реализации. Английские книги были образцами формата; продукт полностью на испанском. Не вводить ИИ-диалоги или генерацию сюжета во время прохождения.

Комплект передаёт утверждённые растровые референсы, структурированные данные и опорные модули логики/озвучки. SVG-персонажи предыдущей версии отклонены и исключены из реализации. Готового интерфейса всей книги в комплекте ещё нет. Предстоит собрать страницы, задания, фоны и сценический реквизит, затем проверить на реальных устройствах.

## 2. Продукт и границы первой версии

Обязательное: обложка/продолжение, 2 подготовительных экрана, все 13 узлов истории с корректными переходами, 3 основных задания после чтения, необязательная другая ветка, сохранение прогресса, сброс, доступность с клавиатуры и касанием, работа без звука.

Интерфейс: `Empezar`, `Continuar`, `Atrás`, `Siguiente`, `Escuchar`, `Pausa`, `Continuar audio`, `Repetir`, `Mostrar texto`, `Ocultar texto`, `Otra historia`, `Empezar de nuevo`. Основное управление постоянно на одном месте. Сброс требует небольшого подтверждения, обычный выбор маршрута — нет.

Текст виден по умолчанию; режим «сначала слушать» включается пользователем. Скрытие текста не скрывает навигацию, подписи вариантов или доступные имена кнопок. Завершение аудио не переводит на следующую страницу. Отсутствие испанского голоса не блокирует прохождение.

В первой версии не нужны авторизация, платежи, аналитические трекеры, сервер, рейтинг, таймеры, очки, микрофон, оценивание произношения и синхронизация альбома между учениками. Страницу альбома можно сохранить локально; общий альбом группы пока собирает учитель из экспортов.

## 3. Архитектура

Vite + обычные HTML/CSS/JavaScript ES modules. Код сценария и заданий хранится в JSON. Специальная библиотека перелистывания не требуется. Если реализация начнётся внутри существующего проекта, допускается его стек при сохранении контракта данных.

Рекомендуемая структура готового проекта:

```text
index.html
src/
  main.js
  renderer.js
  story-engine.js
  browser-narrator.js
  audio-controller.js
  storage.js
  activities/identify.js, match.js, sequence.js, evidence.js, album.js
  styles/book.css, activities.css, responsive.css
public/
  data/story.json, activities.json, scene-manifest.json
  assets/references/*.png        # утверждённые исходные референсы
  assets/scenes/*                # готовые растровые сцены, когда отрисованы
  assets/props/*                 # при необходимости PNG/WebP с прозрачностью
  assets/audio/*                 # позднее, записанная озвучка
```

В передаваемом комплекте JSON лежат в `data/`, растровые референсы — в `assets/references/`; при сборке перенести их под `public/` либо импортировать через Vite последовательно. Не смешивать оба способа адресации.

Компоненты: `BookShell`, `PageRenderer`, `SceneRenderer`, `NarrationControls`, `ChoiceGroup`, `ActivityRenderer`, `ProgressStore`. `StoryEngine` не знает о DOM и браузерной речи. Любой переход вызывает `audioController.stop()` до замены текущего экрана. Данные вставлять через `textContent`/безопасные DOM-узлы, а не конкатенацию HTML из текстов JSON.

## 4. Сценарий и переходы

`data/story.json` — основной машиночитаемый источник. У каждого узла стабильный `id`, тип, `sceneId`, массив `segments`, `next` или `choices`, описание аудио. Терминальный узел имеет `terminal: true`. Реплика содержит `id`, `speaker`, `text`, `speechText`. TTS читает только `speechText`, не служебный заголовок и не подписи кнопок вместе с рассказом.

| Узел | Содержание | Далее |
|---|---|---|
| s01 | Подготовка офренды; фотография у Лусии | s02 |
| s02 | Серьёзный портрет Томаса | s03 |
| s03 | Ветер уносит фотографию во двор | s04 |
| s04 | Искать фотографию / рисовать | a05 / b05 |
| a05 | Кошка лежит на фотографии | a06 |
| a06 | Мяч отвлекает кошку; фотография спасена | a07 |
| a07 | Ещё один семейный снимок: кот на голове Томаса | s08 |
| b05 | Лусия рисует очки и огромные усы | b06 |
| b06 | Гитара и дедушкины песни | b07 |
| b07 | Новый портрет с поющим ртом и гитарой | s08 |
| s08 | Семья собирается; песня / история | end-song / end-story |
| end-song | Семейная песня, кот уходит | post-reading |
| end-story | Бабушкина история; начальные реплики зависят от ветки | post-reading |

Выбор `choose-photo` задаёт `route: "photo"`; `choose-drawing` — `route: "drawing"`. Второй выбор задаёт `ending: "song"` или `"story"`. Четыре сочетания, а не четыре независимых длинных рассказа.

После слияния веток стол продолжает показывать найденный портрет или рисунок. В `end-story` выбирать `variants[route].segments`. Нельзя брать обе версии подряд. `statefulSceneSlots.ofrenda-image` определяет нужный предмет на столе.

На первой развилке обычная кнопка «дальше» заменяется двумя вариантами; переход без выбора запрещён. Кнопки выбора не получают красную/зелёную оценку. Рядом с каждой можно прослушать подпись отдельной кнопкой: это не активирует сам выбор. Не вкладывать одну кнопку внутрь другой.

Назад возвращает точное состояние до перехода. Возврат к s04 и выбор другой ветки очищают старый финал, старую историю последующих экранов, ответы на зависимые post-reading-задания и текущую сборку альбома. Предположение о Томасе и подготовительные задания сохраняются. До изменения выбора простое листание назад ответы не уничтожает. При «Другой истории» начинается противоположный маршрут с s04; первый завершённый результат можно сохранить в отдельном необязательном `completedRuns` без имён учеников.

Прогресс страницы считать по реально пройденному маршруту: «4 из 9» вместо глобального «4 из 13». Два возможных финала имеют одинаковый номер 9. Не показывать ещё не выбранные ветки как пропущенные страницы.

## 5. Подготовка к чтению

Два экрана объединяют уже утверждённые короткие действия. Данные — `activities.json`. Подготовка доступна повторно, её можно пропустить для чтения с учителем.

### P1. Кто есть кто + первое впечатление

Показать Лусию, бабушку и изображение Томаса в рамке. Озвучиваемые реплики: `Soy Lucía.`, `Soy la abuela de Lucía.`, `Tomás es el abuelo de Lucía.` Нажатие на соответствующую карточку оставляет подпись под ней. При неверном выборе — `Mira y escucha otra vez.` без сброса всей попытки.

Далее тот же портрет крупнее: `Busca las gafas y el bigote.` Два существенных hotspot с дополнительным списком кнопок `Las gafas`, `El bigote` для клавиатуры/малого экрана. Координаты hotspot задаются относительно исходного растрового изображения числами от 0 до 1. При масштабировании учитывать фактическую область картинки, включая отступы от object-fit: contain. Координаты не привязывать к пикселям окна.

В конце `¿Cómo es Tomás?` — `Serio`, `Divertido`, `No sé`. Любой ответ принимается, сохраняется `prediction`, оценивания нет. Этот этап создаёт вопрос для чтения.

### P2. Офренда этой семьи

Вводная: `Hoy es el Día de Muertos. La familia recuerda a Tomás.` Четыре предмета с озвучиваемыми названиями: `Flores`, `Agua`, `Pan`, `Foto`. Пользователь соотносит предмет и подписанное/озвучиваемое место. Проверяется узнавание предмета, а не универсальный «правильный набор» культурных элементов.

Базовое управление: выбрать предмет → выбрать место. Drag-and-drop — дополнительное удобство; кнопки и клавиатура дают тот же результат. Выбранная карточка имеет видимое состояние и `aria-pressed`. Заключение: `Es una ofrenda para Tomás.`

Предполагается, что учитель может дополнить культурный контекст. Проект не требует, чтобы ребёнок рассказывал о собственной утрате.

## 6. Чтение и звук

### Временная озвучка

Использовать Web Speech API: `window.speechSynthesis` + `SpeechSynthesisUtterance`. Приложенный `src/browser-narrator.js` реализует базовую очередь по репликам и безопасное прерывание. Это временный синтез на устройстве, качество и набор голосов различаются. Некоторые голоса требуют сети; автономную озвучку можно обещать только при наличии проверенного локального испанского голоса. Книга и её изображения после загрузки могут работать без сети независимо от TTS.

Правила:

1. Проверить оба API. Вызвать `getVoices()` сразу; обновлять список по `voiceschanged`. Пустой список при старте не считать окончательным отсутствием функции.
2. Предлагать только голоса `es`, `es-*`/`es_*`. Приоритет: явно выбранный сохранённый `voiceURI`, затем es-MX, es-ES, любой испанский. Если испанского голоса нет — понятное сообщение `No hay una voz en español disponible. Puedes seguir leyendo.` и повторная проверка по нажатию. Не подставлять молча английский голос.
3. Первый `speak()` запускать непосредственно в обработчике пользовательского нажатия. Не запускать речь при загрузке, после таймера или при входе на страницу.
4. Один активный контроллер речи на приложение. Перед новым чтением, подсказкой, выбором, уходом со страницы и повтором вызвать `cancel()`.
5. Читать последовательно `segments`; сохранить сильную ссылку на текущий utterance. Обработчики проверяют поколение запуска и принадлежность к актуальному utterance, чтобы позднее событие отменённой речи не запустило чужую страницу.
6. `rate` по умолчанию 0.9; доступные пресеты 0.8 / 0.9 / 1.0. `pitch = 1`. Один нейтральный голос для всех ролей в первой версии. Не имитировать детский голос изменением высоты.
7. Пауза в базовом адаптере реализована как остановка с запоминанием индекса текущей фразы. `Continuar audio` начинает эту фразу заново. Отразить это в доступной подсказке: `Continúa desde el principio de la frase.` Точный возврат к слову не обещать. Позднее файловое аудио сможет иметь обычную точную паузу.
8. Подсветка только текущей реплики через `onstart/onend`; словесная подсветка по `boundary` не обязательна и не должна влиять на функциональность. Анимации не зависят от точности TTS-таймингов.
9. Во время фонового скрытия страницы остановить звук. При возврате требуется новое нажатие. На странице прототипа проверить системные голоса; на реальном Android/iOS отдельно проверить цепочку из нескольких реплик.
10. Отдельные ветки `unsupported`, `voice-unavailable`, `error`. При ошибке снять подсветку, дать повтор и оставить текст/навигацию. Watchdog в адаптере ловит только отсутствие старта; фиксированный таймаут окончания длинной реплики не применять.

Кнопка слушания варианта/предмета использует тот же контроллер, а не второй экземпляр. Скорость/голос применяются при следующем запуске; изменение настроек во время чтения останавливает текущую речь.

### Позднейшая замена

`AudioController` предоставляет `play(segments, audio)`, `pause()`, `resume()`, `stop()`, `setOptions()`, события состояния/реплики. Сегодня он делегирует `BrowserNarrator`. Позднее `audio.src` указывает записанный файл; контроллер использует `HTMLAudioElement`. Остальные компоненты и JSON-текст не переписываются. Ошибка/отсутствие записи может предлагать TTS по нажатию.

Источники API: [SpeechSynthesis](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesis), [voiceschanged](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesis/voiceschanged_event), [cancel](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesis/cancel).

## 7. Задания после чтения

### E1. Nuestra historia

Четыре картинки выбранной ветки. Переставить в хронологическом порядке, затем `Comprobar`. Для photo: ветер → кошка на фото → мяч → возвращение фотографии. Для drawing: ветер → начало рисунка → гитара → готовый портрет.

Перемещение: выбрать карточку и место, либо кнопки «раньше/позже»; мышью можно перетаскивать. DOM-порядок совпадает с видимым. Успех: `Esta es nuestra historia.` и доступный короткий пересказ. Ошибка: `Mira las imágenes. ¿Qué pasa primero?` Сохранять текущую расстановку, не отдавать автоматически готовое решение. Нет штрафа за повтор.

### E2. ¿Serio o divertido?

Показать исходное предположение. Снова предложить `Serio`, `Divertido`, `Serio y divertido`, `No sé`. Затем выбрать значимую картинку пройденной ветки и озвучить опору `Tiene un gato en la cabeza.` / `Le gusta cantar.`

Это интерпретация. Не кодировать «divertido» как единственный правильный ответ и не блокировать продолжение: серьёзный вид и любовь к шуткам совместимы. Обратная связь: `Mira la imagen. ¿Por qué?` Сохранять выбор для обсуждения с учителем, не присваивать балл.

### E3. Otra foto de Tomás

Конструктор вымышленной страницы альбома. Фон: сад / кухня / гостиная. Предмет: кот / гитара / мяч. Томас остаётся фигурой в созданном рисунке, а не появляется живым среди семьи.

Фразовые блоки: `Tomás está en el jardín/la cocina/el salón.`, `Tiene un gato/una guitarra/una pelota.`, `Le gusta cantar/jugar con el gato/jugar con la pelota.` Выборы образуют реальные грамматически корректные фразы. Разрешены все осмысленные комбинации, автоматического «исправления» фантазии нет.

Сохранить структурированные данные в localStorage. Экспортировать PNG со сценой и подписью через canvas: отрисовать локальные PNG/WebP и текст системным шрифтом, вызвать toBlob() и скачать файл по нажатию. Дать альтернативу копирования подписи. Использовать ресурсы своего origin, чтобы не получить tainted canvas. Если отдельные прозрачные персонажи ещё не готовы, конструктор допускает выбор заранее нарисованных цельных картинок и фраз; не заменять героев примитивной векторной графикой. При ошибке экспорта оставить просмотр результата и копирование подписи. Общий альбом без сервера не синхронизируется автоматически.

### E4. ¿Y si…? — необязательно

После заданий предложить другую ветку. Не заставлять проходить её для отметки «книга завершена». Вернуть на первую развилку; повторные задания используют новый маршрут, исходный результат можно оставить в истории прохождений.

## 8. Растровые иллюстрации и визуальное производство

SVG-персонажи предыдущей версии отклонены пользователем. Не использовать их, не трассировать и не перерисовывать героев вручную кодом. Иллюстрации книги — PNG/WebP. Сценарий, задания, HTML-текст и навигация остаются прежними. Для интерфейса достаточно HTML/CSS и обычных доступных кнопок.

### Утверждённый стиль

Плоская гуашь + карандаш: угловатые лица, маленькие глаза, спокойный интерьер, тёплая бумага, синий, терракотовый и оранжевый. Сохранять характер рисунка, пропорции, причёски и одежду по `assets/references/approved-style.png`. Цвета и небольшие детали определяются самим референсом, не старой векторной палитрой.

Лусия: короткое тёмное каре с чёлкой, белая футболка, синий сарафан, белые носки, чёрные ботинки. Бабушка: высокая и худая, короткие седые волосы, светлая кофта с голубыми полосами, терракотовые брюки, тёмная обувь. Чёрный кот — тонкий силуэт. Мама, брат и Томас в других позах должны быть дорисованы в этой же стилистике; отклонённые SVG не являются референсом их лиц.

### Порядок работы

1. Codex собирает вертикальный срез на сценах s02 и s04 с этими картинками: настоящий текст, озвучка, адаптация и рабочий переход в любую ветку.
2. Для ещё не нарисованных сцен использовать явные временные заглушки в прототипе. Не подставлять одну неподходящую картинку под все события и не выдавать такие страницы за готовый визуальный результат. Временная подпись на испанском: `Ilustración en preparación`.
3. После проверки размеров текстового блока, рисунка и управления сформировать список недостающих иллюстраций из scene-manifest.json. Указать для каждой событие, персонажей, состояние предметов, композицию desktop/mobile и необходимые слои.
4. Недостающие иллюстрации генерируются отдельно с приложенным утверждённым референсом; согласовываются до вставки. Основное визуальное производство можно продолжить в этом чате, а готовые файлы передать Codex для подключения. Наличие у Codex инструмента генерации изображений не предполагается автоматически.
5. После замены заглушек проверить непрерывность сцен: внешний вид героев, местоположение мебели, рамка/фотография/рисунок, направление двери, опоры рук и ног. Подключение файлов не меняет сценарий и логику.

### Изображения и масштабирование

Для каждого типа композиции хранить отдельные desktop/mobile-файлы. Использовать `<picture>` с `<source media="…">` или эквивалентную компонентную логику; указывать width/height/aspect-ratio для предотвращения скачков вёрстки. Для всего изображения — object-fit: contain. Обрезать героев через cover без проверки нельзя.

Ориентир разрешения: исходник не меньше примерно 2× фактической ширины показа. Например, для рисунка шириной 900 CSS px на desktop нужен исходник около 1800 px; для ширины 390 CSS px на телефоне около 780–1170 px. Это бюджет под реальные экраны, а не бесконечное векторное масштабирование. Пустую область вокруг рисунка учитывать при расчёте полезной плотности пикселей. Не растягивать маленький файл ради формального размера 2×.

PNG оставить мастер-файлом; WebP готовить как веб-копию с визуальной проверкой лица, карандашного контура и мелких предметов. Сохранять пропорции. Текст всегда HTML. Не получать SVG переименованием, обёрткой с `<image>` или автоматической трассировкой. Не накладывать генеративные «бумажные» шумы поверх текста.

### Анимация

Базовая версия использует цельные статичные сцены. Для важных движений можно отдельно подготовить фотографию, мяч или кота в PNG/WebP с настоящей прозрачностью и чистый фон без этого объекта. Двигать через CSS transform/opacity. Если корректные слои ещё не готовы, использовать статичную конечную сцену или две подготовленные картинки с коротким переходом.

Не вырезать объект из цельной иллюстрации так, чтобы в фоне оставалась его копия или дыра. Не требовать от разработчика покадровой перерисовки лиц. Моргание и мимика не обязательны. Смысл истории должен сохраняться без анимации.

`scene-manifest.json` перечисляет все 13 сцен, имеющиеся референсы и недостающие ассеты. Поля готовности не заполнять фиктивными путями. Файлы новых иллюстраций добавляются только после фактической отрисовки.

## 9. Адаптивная композиция

Desktop от примерно 900 CSS px: книжный разворот в контейнере max-width 1440 px; текст слева, сцена справа. Между ними воздух; у сцены самостоятельный контейнер. Текст 22–28 px, межстрочный 1.4–1.55, строка примерно 30–45 знаков. Это стартовые параметры, не жёсткое масштабирование макета.

Телефон/узкий планшет: одна страница, иллюстрация сверху, текст ниже, затем управление. Сцену перекомпоновать вертикально с крупными фигурами; её область может быть 4:3 или близкой после исключения пустой зоны для текста из прежнего макета 9:16. Не вставлять одновременно всю высокую картинку с пустым низом и дополнительную такую же пустую область в CSS. Рост текста увеличивает страницу и естественную прокрутку; не ужимать шрифт, чтобы поместить всё в экран.

Текст 18–22 px, line-height около 1.45; кнопки минимум 48×48 CSS px с расстоянием 8–12 px. Две длинные альтернативы на узком экране размещаются вертикально. Меню текста/озвучки не закрывает сцену. Нижняя панель либо в потоке, либо sticky с корректным padding-bottom и `env(safe-area-inset-bottom)`; она не перекрывает последнюю строку.

Контрольные ширины: 360, 390, 768, 1024, 1440 px; горизонтальная ориентация телефона; масштаб браузера 200%. Внутри книги нет горизонтального скролла. Крупные элементы интерьера допускают обрезку краем сцены; лица, руки с важным предметом и выборы — нет.

`data/scene-manifest.json` перечисляет 13 сцен, рекомендуемые базовые позы и статус. Он намеренно не выдаёт ещё не созданные фоны за готовые ассеты.

## 10. Движение

Только короткие события: полёт фотографии (s03), движение мяча/кота (a06), при необходимости однократный взгляд. Состояние иллюстрации понятно без движения и звука. Не добавлять непрерывное моргание, покачивание всех персонажей, частицы, анимированный курсор и фоновую музыку.

Длительность сюжетного движения около 600–1200 мс; переход страниц 120–220 мс. При `prefers-reduced-motion: reduce` сразу финальная статичная композиция и обычное появление страницы. Возврат назад не обязан повторять событие; повтор доступен отдельно. Не двигать текст во время чтения. Если добавлено перелистывание CSS 3D, скрытая сторона недоступна фокусу и скринридеру, после перехода фокус получает заголовок страницы.

## 12. Доступность и устойчивость

`html lang="es"`; один понятный заголовок экрана; native buttons/radio groups; видимый фокус; подписи и состояние выбора доступны скринридеру. Enter/Space активируют, Tab не попадает на скрытые страницы. После смены экрана переводить фокус к заголовку; текст реплики TTS не дублировать целиком через aria-live. Статусы заданий/озвучки — короткий `aria-live="polite"`.

Сюжетная сцена имеет один лаконичный alt/описание, не сотню озвучиваемых декоративных paths. Интерактивный портрет из pre-reading получает отдельные доступные кнопки по объектам. Декоративные изображения и слои — aria-hidden. Интерактивные элементы имеют доступные подписи.

Состояние не передаётся одним цветом. Контраст текста/контролов проверяется отдельно от декоративной палитры; для текста на бумаге использовать тёмный контурный цвет. Кнопки не рисовать внутри картинки. Выборы и задания полностью доступны без drag-and-drop и без звука.

Если отсутствует фон — оставить нейтральную сцену/alt и доступный текст; не блокировать рассказ. Загружать текущую и следующую нужную сцену, не весь набор в высоком разрешении. Изображения загружать из собственных локальных ассетов. Не импортировать произвольный пользовательский HTML в DOM.

## 14. Приёмка

- Все четыре комбинации route×ending достижимы и показывают правильный предмет/реплики; порядок экранов корректен.
- Назад и повторный выбор не смешивают маршруты; повторная загрузка восстанавливает текущую ветку.
- Проверены прерывание речи переходом, быстрая серия нажатий, пауза/продолжение с начала фразы, пустой список голосов при старте, отсутствие испанского голоса, поздние события старого utterance.
- Без TTS доступны все экраны, задания, текст и финалы. После возврата во вкладку нет самопроизвольной речи.
- Расстановка E1 зависит от ветки. E2 принимает все интерпретации. Конструктор E3 даёт правильные формы фраз и сохраняет результат.
- При обновлении страницы сохраняются прогресс/выборы; сброс затрагивает только эту книгу.
- На 360–1440 px, при 200% и landscape-телефоне ничего не перекрывается, нет горизонтального скролла, кнопки пригодны для касания.
- Проверены Chrome/Edge/Firefox на компьютере и как минимум Safari iOS + Chrome Android на реальных устройствах. Проверка модулей логики в комплекте не заменяет это.
- Растровые иллюстрации имеют достаточную полезную резкость на целевых экранах; герои соответствуют утверждённому референсу. Ноги стоят на полу, руки держат реквизит, ножки мебели имеют опоры. Отклонённые SVG нигде не используются.
- `prefers-reduced-motion` отключает движения; отсутствуют постоянные декоративные циклы.
- Исходный сценарий сохранён. Если при редактуре обнаружена сюжетная/языковая проблема, записать её на согласование и не придумывать новую ветку самостоятельно.
