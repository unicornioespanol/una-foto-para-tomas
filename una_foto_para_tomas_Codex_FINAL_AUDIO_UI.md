# Una foto para Tomás — финальная интеграция аудио и доводка интерфейса

**Статус:** озвучка пользователем **закончена**; все подготовленные записи сложены в папку ассетов текущего локального проекта. Нужно интегрировать, проверить и исправить конкретные проблемы, **не генерируя ничего заново**.

**Главная цель:** законченная локальная книга, одинаково корректная на телефоне и компьютере, со всеми ветками истории и всеми подготовленными аудиозаписями.

## 0. Жёсткие границы задачи

- Работать **в текущем проекте**. Сначала изучить его реальную структуру, `story.json`, `activities.json`, аудиопапку, существующие `AudioController`/`BrowserNarrator`, аудиокомпоненты и `QA_REPORT.md`.
- **Не менять утверждённый сценарий**, тексты реплик, структуру четырёх вариантов прохождения, задания и иллюстративный стиль.
- **Не подключать, не переделывать и не мигрировать** сервер, PostgreSQL/PGlite, телеметрию, Firebase, Supabase, систему согласий или `/admin/analytics`. Существующие вызовы событий должны продолжить работать; отдельно сохранить их совместимость с файловым аудио.
- **Не публиковать** проект, не разворачивать хостинг и не выполнять платные операции; не требовать платных сервисов, ключей API и банковской карты.
- **Не вызывать ElevenLabs, Kie или системный TTS для повторной генерации озвученных реплик.** Подключить существующие MP3 из папки пользователя.
- Работать без придумывания имён файлов. Таблицы ниже — ожидаемые роли и *целевые имена* дополнительных файлов. В первую очередь проверить фактические имена, расположение и содержимое ассетов. При расхождениях сделать явную таблицу соответствия и сообщить, что не удаётся однозначно сопоставить. Не переименовывать исходники без необходимости.

## 1. Подключение готового аудио: сюжет

Установить устойчивое отображение `story node / variant → audio file` в отдельном манифесте или в существующей системе конфигурации (без правок текста истории).

Ожидается **14 уникальных аудиоблоков** основного сюжета:

| Блок | Где используется |
|---|---|
| `s01` | Общая сцена |
| `s02` | Общая сцена |
| `s03` | Общая сцена |
| `s04` | Первая развилка |
| `a05`, `a06`, `a07` | Только ветка `photo` |
| `b05`, `b06`, `b07` | Только ветка `drawing` |
| `s08` | Вторая развилка, общая сцена |
| `end-song` | Финал `song` независимо от предыдущего маршрута |
| `end-story` + `route=photo` | Версия финала-истории после `photo` |
| `end-story` + `route=drawing` | Версия финала-истории после `drawing` |

Итого 5 общих + 3 + 3 + 1 + 2 = **14**. Проверить каждую запись: реальное воспроизведение, начало/конец, верный текст и отсутствие перепутанных вариантов. Если запись включает несколько персонажей — не дробить её автоматически; если пофразная — сохранить точную последовательность.

**Обязательно:** для `end-story` использовать разные MP3 по `route`. Не выбирать по одной только сущности `end-story`. При `s08` не перепутать альтернативные кнопки с дорожкой повествования.

**Принципы:**
- «Кто есть кто»: отдельная запись для каждой реплики; при повторе — только её аудио, не вся последовательность.
- Гафас/биготе: это **два последовательных шага**, не старое общее `Busca las gafas y el bigote.`. Если интерфейс уже изменён, привязать к нынешним текстам.

- Если обнаружатся **другие** готовые файлы (инструкции, feedback, названия объектов, E3 и т. п.), составить их инвентаризацию и привязать к реально существующим кнопкам; **не создавать новых кнопок только потому, что лежит MP3**.
- Если важный MP3 отсутствует — показать в отчёте, что конкретно отсутствует; не заменять его молча неизвестным системным голосом.

## 3. Плеер и взаимодействие со страницами

- Сохранить архитектуру `AudioController` и совместимость интерфейса, но для основных сцен перейти на подготовленные файлы.
- Для полного аудио: `Escuchar`, `Pausa`, `Continuar`, `Repetir` со смысловыми состояниями. Пауза/возобновление должны работать с текущей позиции; `Repetir` — с начала записи.
- **Любой переход, смена маршрута, возврат и перезапуск** останавливают прошлую запись. Старые обработчики/асинхронные события не запускают аудио от покинутой страницы.
- Короткая подсказка не должна накладываться на сюжетное аудио: единый аудиоменеджер/политика прерывания.
- На мобильных не полагаться на autoplay: основная запись запускается **по действию пользователя**, не при загрузке или открытии страницы. Завершение аудио не перелистывает страницу автоматически.
- Текстовые режимы и книга полностью работоспособны при выключенном звуке/недоступном аудио.
- Не обещать подсветку по словам без реальных таймкодов. Если есть подсветка строки, она должна быть синхронизирована корректно; иначе оставить обычный читаемый текст.
- Проверить, нет ли в MP3 уже звука ветра (`s03`) или напева (`b06`); не накладывать эффекты поверх готовой записи автоматически.
- Файлы держать отдельными веб-ресурсами в сборке; **не вшивать все MP3 в большой автономный HTML**. Для офлайн/`file://` честно указать потребность в соседней папке аудио либо отдельном корректном офлайн-пакете. Проверить корректность путей `dev`/`build`/прямая загрузка.
- Сохранить ранее реализованные события телеметрии `audio_play`, `audio_pause`, `audio_replay` (и т. п. в существующей схеме) без изменения сервера и БД.

## 4. Antes de leer: порядок «¿Quién es quién?»

Сейчас карточки `Lucía / Abuela / Tomás` выставлены по порядку предъявления реплик — это подсказка ответов.

- Перемешать **положение карточек**, независимо от порядка, в котором идут озвучиваемые реплики. Не менять их портреты, значения, идентификаторы и правильные ответы.
- Зафиксировать перестановку на попытку; она не должна «прыгать» после нажатия, ошибки или возврата. При сохранении попытки восстанавливать её расположение.
- Проверить, что нельзя пройти по схеме «первый звук — первая карточка, второй — вторая, третий — третья». Для трёх карточек допустимо выбирать только из перестановок, отличных от исходной; не переставлять карточки заново при каждом воспроизведении.
- Неверное действие не раскрывает автоматически ответ, верные решения сохраняются.

## 5. Убрать лишний `Ajustes` после подключения файлов

- Изучить, за что реально отвечает `Ajustes`. Убрать устаревший выбор системного TTS-голоса, системную скорость/высоту и подобные настройки, если они больше не применимы.
- Если после удаления TTS-настроек в `Ajustes` ничего полезного не остаётся — убрать сам пункт. Если там остаются нужные настройки чтения/доступности — сохранить их в понятном месте.
- Не удалять работающие `Mostrar texto` / `Ocultar texto` и управление воспроизведением.

## 6. Исправить наложение `Comprobar`

- Кнопка `Comprobar` и обратная связь не должны перекрывать карточки, поля, нижнюю навигацию и другие кнопки.
- Исправить сетку/высоты/отступы, а не скрыть проблему `overflow: hidden` или `z-index`.
- Проверить при 360×800, 390×844, 844×390, 720×450, 1280×720 и 1366×768, включая состояние ошибки и правильного ответа. Минимальный touch target — 44×44 CSS px.
- Не допускать горизонтальной прокрутки. На очень малой высоте разрешить естественную вертикальную, чтобы контент не пропадал.

## 7. Кот: поправить глаза в исходных иллюстрациях

- Встречающийся в сценах кот сейчас выглядит пугающе из-за слишком светлых глаз без читаемых зрачков.
- Исправить **именно готовые растровые ассеты**: сделать тёмные видимые зрачки, тёплые янтарные радужки, естественный спокойный взгляд. Сохранить размер, положение, мех/форму силуэта, фактуру гуаши, свет и композицию. Не рисовать постоянные CSS-точки поверх глаз и не заменять персонажа новым.
- Проверить все иллюстрации с котом в desktop и mobile, включая разные концовки, если он там показан.
- **Если в среде Codex нет средств аккуратно редактировать PNG/WebP без ухудшения**, не симулировать исправление и не портить ассеты: указать точные пути нужных изображений и оставить задачу на точечное графическое исправление.

3. Прогнать тесты проекта, проверить responsive на указанных размерах и отразить, что реально проверено браузером, а что не проверено на физическом телефоне.
4. Сделать отдельную таблицу **`ID узла/кнопки → реальный путь к MP3 → статус подключения`**, списки лишних/неоднозначных/отсутствующих аудио и исправленных ассетов.
5. Указать точные изменённые файлы, результаты тестов и обновить `QA_REPORT.md`. Если часть задач заблокирована, ясно указать, что блокирует.
6. **Остановиться.** Не размещать в интернете, не менять СУБД, не подключать платные сервисы и не запускать публичный сбор данных.

**Приоритет:** работающее файловое аудио → исправление `¿Quién es quién?` → `Comprobar` → `Ajustes` → кот → полный QA. Не начинать следующий проект или дополнительную разработку функций.
