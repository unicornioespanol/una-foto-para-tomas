# Подготовка по codex_deploy.md · 3 ноября 2026

**Подготовка выполнена локально. Публикации нет. Подключение к созданной Neon отложено владельцем.** Для приёмки именно Neon и публичного HTTPS нужны последующие шаги из [DEPLOY_RENDER_NEON.md](DEPLOY_RENDER_NEON.md).

## Фактический аудит

До доработок уже были Express, `pg`, постоянный development PGlite, SQL-схема, серверные согласия/отзыв/удаление, scrypt-пароли, сессии в БД, CSRF, allowlist событий, дедупликация, CSV/JSON и Docker-конфигурация. Прежние проверки не доказывали работу отдельного PostgreSQL-процесса. Отдельного ключа подписи сессий в этой архитектуре нет: случайные токены хешируются в БД. Его не придумывали и стек не меняли.

Были пробелы: production не принуждал verified TLS, хост по умолчанию был loopback, не было SPA fallback, bootstrap печатал пароль, ignore не покрывал все `.env*`. Они устранены. Само наличие созданной Neon не доказывает подключение — URL в проекте отсутствует и не запрашивался в чате. Git-репозиторий в папке отсутствует; staged-файлов/remote/push нет.

## Изменения

- `server/db.mjs`: production только `pg` + `DATABASE_URL`, проверяемый TLS и имя хоста (`verify-full`), отказ небезопасным режимам. Пул 5 соединений, connect timeout 15 s, канал SCRAM binding включён. Транзакционная повторяемая миграция с advisory transaction lock; SQL-схема не переписана.
- `server/index.mjs`: `PORT` из окружения, default host `0.0.0.0`; безопасные сообщения об ошибках вместо URL/SQL stack. Retention выполняется также при старте, чтобы сон Free не откладывал её бесконечно.
- `server/app.mjs`: `/healthz` проверяет БД; SPA fallback только для HTML GET, API и отсутствующие assets сохраняют JSON/404; production требует точный HTTPS origin без пути. Готовый dist и API обслуживает один процесс. Существующие auth/CSRF/consent/delete/event checks сохранены.
- `server/cli.mjs`, `server/terminal.mjs`: локальные migrate/check/create-admin/retention; пароль вводится скрыто с подтверждением либо читается из приватного файла, не печатается. Нет setup endpoint, парольного аргумента, администратора в build/start.
- `.env.example`, `.gitignore`, `.dockerignore`: шаблон без секретов, исключены все приватные env, ключи, дампы, runtime/backups/test-results и offline-артефакты. SQL-миграции разрешены отдельно от дампов. Предупреждение: ручная веб-загрузка в GitHub игноры не применяет.
- `render.yaml`, package/lock: Node 24.x, Free, ручной auto-deploy, существующие build/start, env через Environment. В lock изменена только корневая engines-запись; версии зависимостей не менялись.
- `tools/postgres-check.mjs`: тест отдельной PostgreSQL по TLS в своей случайной схеме с очисткой, полный API-набор и restart дочернего Node. `tools/deploy.test.mjs`: конфигурация, маршруты/MP3 Range, off, закрытый export и bootstrap без вывода секрета. Обычные server/research тесты не используют случайно унаследованный production DATABASE_URL.
- `tools/pg-tool.mjs`: локальный custom-format dump и restore в пустую БД, пароль только через окружение subprocess; backup не перезаписывается, restore без `--clean`. Исправлена проверенная проблема Windows: native pg_dump теряет акцент в абсолютном пути `día`; используется временный ASCII basename и копирование через Node. Для шифрования описан стандартный GnuPG, собственная криптография не добавлялась.
- Старый `compose.yaml` приведён в соответствие обязательному TLS: нужны локальные сертификаты и root cert mount; это альтернативный путь, для Neon/Render Docker не нужен. README_SERVER и инструкция обновлены. Docker здесь не запускался.

## Не подтверждено и что осталось

- **Neon не подключалась** по решению владельца «Подключение проверим позже». Тестовый сценарий и безопасный способ передать URL локально готовы; подключение, миграции целевой Neon и настоящий администратор ещё не выполнены.
- **Render/GitHub/HTTPS не публиковались**, аккаунты, доступность Free для владельца, реальный регион Neon, cold start и лимиты не проверены в кабинете. Free-конфигурация подготовлена; никаких платных ресурсов не создавалось.
- Полный зашифрованный backup **вашей Neon** и его восстановление ещё предстоят. Проверен обычный PostgreSQL dump/restore; GnuPG в этой среде отсутствует, само шифрование не выполнялось. Не выдавать тестовый локальный dump за резервную копию Neon.
- Настоящие телефоны и браузеры владельца не проверены. Публичная телеметрия остаётся off; research можно проверять на отдельном согласованном техническом стенде. Данные настоящих детей не создавались.
- Условия прав на аудио перед публикацией подтверждает владелец. Наличие упоминания ElevenLabs в ТЗ не доказывает происхождение конкретных MP3; контент/атрибуцию самовольно не меняли.

Критерии ТЗ, требующие публичной ссылки и проверки Neon, **не отмечены выполненными**: пользователь поручил подготовку без публикации. Следующий шаг — локальная проверка тестовой Neon, когда владелец будет готов, затем отдельное решение о первом выпуске.
